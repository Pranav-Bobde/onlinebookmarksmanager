# Product

## Register

product

## Users

Pranav is the first user. He encounters useful URLs in browsers, chats, documents, and terminals, and wants to save them without deciding a title, folder, or tag first. Similar developers and indie makers are possible later users, not an MVP requirement.

## Product Purpose

onlinebookmarksmanager.com is a private personal bookmark tool for one repeated job: dump a URL now and find it later from whatever the user still remembers.

The URL is the only required input. The app saves it immediately, extracts useful page context in the background, suggests tags from a closed candidate set, and searches user-entered and extracted context. The MVP succeeds when Pranav prefers it to his current bookmark workflow and reliably recovers URLs from vague remembered terms.

## Brand Personality

Minimal, direct, fast. The interface should feel current without adding visual or interaction overhead. Copy should use short plain language and explain failures without product jargon.

## Anti-references

- Do not reproduce the dated, high-friction onboarding and dense visual impression Pranav encountered in Raindrop and Booky.
- Do not turn the app into a knowledge-management dashboard, read-later product, visual mood board, or team workspace.
- Avoid decorative SaaS styling, large marketing surfaces inside the app, mandatory filing steps, and feature-heavy navigation.

## Design Principles

- Save first. The URL-only path must never wait for optional metadata or filing choices.
- Search from memory. Vague remembered words matter more than exact titles or folder recall.
- Keep automation reviewable. Suggested tags and extracted fields remain visible, correctable, and allowed to abstain.
- Fail without losing the bookmark. Extraction and preview failures must leave a usable saved URL and a clear retry path.
- Prefer one obvious action per state. Extra metadata and controls appear only when they help the current task.

## Accessibility & Inclusion

Target WCAG 2.2 AA for contrast, keyboard use, focus visibility, form labels, and semantic structure. Support reduced motion. The responsive web experience must preserve capture and search on mobile without pretending to be a native app.
